## Threat model (STRIDE)

Prelum is a publishing library plus a static specimen. Callers pass markdown, post rows, and image resolvers. The specimen Worker only redirects `http:` to `https:` and then serves built assets.

- Spoofing. The library has no accounts. The specimen has no login.
- Tampering. Markdown is the untrusted input. Raw HTML is dropped (`remark-rehype` without `allowDangerousHtml`). The URL policy runs on `a href` and `img src` after the other plugins. KaTeX `trust` is left unset. `assertSafe` is a second parser scan, off unless the caller opts in. The specimen opts in.
- Repudiation. No audit log. A library does not need one.
- Information disclosure. Feed and sitemap text go through `escapeXml`. The history search below found no credentials.
- Denial of service. `DEFAULT_MAX_BYTES` is 512 KB and `DEFAULT_MAX_DEPTH` is 100. The README already says a bracket run under that byte cap can still take seconds, and that the cap is the caller's to set.
- Elevation of privilege. The library holds no privilege. `code-map.yml` grants `contents: write` to a called workflow with static inputs. That grant is the map publish, and it is not a pull-request shell.

## 4. Data integrity

`escapeXml` encodes `&`, `<`, `>`, `"`, and `'`. `escapeXmlText` encodes the first three and is documented as element text. `cdata` splits `]]>`. `absolutiseUrls` rewrites double-quoted `href`, `src`, and `srcset` values that start with a single slash, and it says so. Sitemap `loc`, `changefreq`, and image `loc` are escaped. `priority` is printed with `toFixed(1)`. Fixture tests reproduce germomics, foxhound, and dustinedwards-info documents byte for byte.

PL-2. Area: data integrity (and correctness). Severity: MINOR. Confidence: measured on this host.

`rfc822` and `isoDay` go through `toDate` (`xml.mjs` lines 72 to 79), which reads SQLite `YYYY-MM-DD HH:MM:SS` as UTC. The README and `xml.mjs` lines 44 to 46 document that. `rssItem` (lines 25 to 27), `atomEntry` (lines 95 to 96), the Atom feed's newest timestamp (line 138), `feedItem` (lines 180 to 185), and sitemap `datetime` (lines 69 to 71) call `new Date(string)` instead. On this machine (`America/Chicago`), `rssItem` of `2026-06-21 09:30:00` emitted `Sun, 21 Jun 2026 14:30:00 GMT`. `rfc822` of the same string emitted `Sun, 21 Jun 2026 09:30:00 GMT`. Atom `published` and JSON `date_published` were `2026-06-21T14:30:00.000Z`. Sitemap `lastmodFormat: "datetime"` was the same shifted instant. The default day format uses `isoDay` and stayed `2026-06-21`. Feed tests pass ISO strings and `Date` objects, so they stay green. A UTC host (GitHub Actions, a Worker) hides the shift because local time there is UTC. A local build that passes a D1 datetime string does not. Smallest fix: route those five call sites through `toDate`.
